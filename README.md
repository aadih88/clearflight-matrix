# ClearFlight — Compliance Traceability Matrix

A structured, browsable traceability matrix for a slice of India's DGCA UAS certification requirements — built to test how far LLM-assisted extraction from a real regulatory document can be trusted, not just demoed.

**Live app:** [link] · **Full technical spec:** [SPEC.md](./SPEC.md)

## What this is

17 sub-clauses from DGCA's *Certification Scheme for Unmanned Aircraft Systems* (Structure, and Material and Construction sections) turned into a structured, filterable table — what each clause requires, how DGCA says to verify it, which subsystem it touches, and whether it depends on an external standard (ISO/IEC/ASTM/IS).

It's a table, not a chatbot. The extraction ran once, offline; the running app only ever reads a static JSON file — no live LLM calls, no API key needed to use it.

## Why

Requirements traceability — the line from a design decision back to the regulation that drove it, and forward to the evidence that proves it — is one of those problems that looks simple until you try to build it, especially against a real regulatory document instead of a clean internal spec. I wanted to see how much of that could be made structural rather than tribal knowledge, and to be honest with myself about where an LLM extraction pipeline actually earns trust and where it doesn't.

## What's here

- **`data/matrix.json`** — the matrix itself: 17 rows, one per sub-clause. 4 of them cite an external standard.
- **`app.py`** — the Streamlit viewer: filterable, searchable, reads `matrix.json` and nothing else. No login, no live API calls.
- **`extract.py`** — the pipeline that produced `matrix.json`: splits the hand-transcribed source text into per-clause chunks, calls an LLM once per clause with a structured-output schema, validates the result, and writes the data. Also checks that every standard named in a clause's source text made it into the output, retrying once if not.
- **`source/`** — the hand-transcribed source text for the 17 sub-clauses, checked column-by-column against the gazette's table layout.
- **`SPEC.md`** — the full build spec: schema, extraction prompt, pipeline steps and acceptance criteria.

## How it works

1. **Source extraction** — raw text for the 17 sub-clauses, taken from the gazette PDF.
2. **LLM extraction** (`extract.py`) — one structured-output call per clause, validated against a strict schema (see [SPEC.md](./SPEC.md) for the full schema and prompt).
3. **Evaluation** — every row graded by hand against the source text before publishing, the same discipline an AI eval demands: check the actual output against ground truth, not just whether it looks plausible.
4. **Streamlit app** (`app.py`) — reads the static output, nothing else.

## Data & disclosure

- `data/matrix.json` was generated by an LLM. The model is recorded in `data/provenance.json` and shown in the app.
- Every row was evaluated by hand against the source document before this was published.
- This is a **draft reference, not an authoritative or certified source**. Always verify against the actual DGCA document and consult a qualified engineer before relying on anything here for a real compliance decision.
- Source: Certification Scheme for Unmanned Aircraft Systems (26 Jan 2022), Part 3, Annexure A, Section 4 (Structure) and Section 5 (Material and Construction), gazette pages 140-143. [DGCA portal](https://www.dgca.gov.in/digigov-portal/?baseLocale=en_US?page=5068/4998/servicename) — search Drones/UAS for the Certification Scheme and related documents; this page does not link to it directly.

## Run it yourself

```bash
pip install -r requirements.txt
streamlit run app.py
```

No API key required to run the app — it only reads the static `data/matrix.json` already in the repo.

## Reproduce the extraction

```bash
export OPENAI_API_KEY=sk-...
python extract.py
```

Generates `data/matrix.json` and `data/provenance.json` from `source/cs_uas_annexure_a_structure_material.txt`. See `SPEC.md` for the schema and the full extraction prompt.

## Scope

One slice of one regulation: the Structure, and Material and Construction sections of DGCA's UAS certification criteria (17 clauses). Not a complete certification tool, and not a substitute for reading the source document or getting sign-off from a qualified engineer.
